# Аналитический дашборд репозитория - Документация по виджетам

## Обзор

Аналитический дашборд репозитория предоставляет всесторонние данные об активности репозитория и паттернах коммитов. Он состоит из нескольких виджетов, которые анализируют различные аспекты данных репозитория, от высокоуровневой статистики до детальной информации о коммитах.

## Архитектура виджетов

Дашборд построен с адаптивной сеточной компоновкой, которая подстраивается под различные размеры экрана. Каждый виджет спроектирован как самодостаточный компонент со своей стилизацией и логикой обработки данных.

## Описание виджетов

### 1. Виджет обзорной статистики
**Назначение**: Предоставляет высокоуровневую сводную статистику по анализу репозитория.

**Источник данных**: 
- `total_commits`: Общее количество проанализированных коммитов
- `analysis_period.start`: Дата начала периода анализа
- `analysis_period.end`: Дата окончания периода анализа

**Визуальный дизайн**:
- Виджет на всю ширину, охватывающий всю сетку
- Трехколоночная компоновка с центрированной статистикой
- Градиентные эффекты для значений
- Эффекты наведения с усиленными тенями

**Ключевые метрики**:
- **Общее количество коммитов**: Показывает общее количество коммитов в анализе
- **Начало анализа**: Начальная дата диапазона коммитов
- **Конец анализа**: Конечная дата диапазона коммитов

### 2. Виджет общей статистики
**Назначение**: Отображает всестороннюю статистику коммитов и метрики производительности.

**Источник данных**: Объект `overall_stats`, содержащий:
- `total_commits`: Общее количество проанализированных коммитов
- `total_lines_added`: Сумма всех добавленных строк по коммитам
- `total_lines_removed`: Сумма всех удаленных строк по коммитам
- `net_lines_changed`: Чистое изменение (добавлено - удалено)
- `total_files_changed`: Общее количество измененных файлов
- `average_commit_size`: Средний размер коммита в строках
- `average_commits_per_day`: Ежедневная частота коммитов
- `average_changes_per_day`: Ежедневный объем изменений кода
- `average_files_per_commit`: Среднее количество файлов на коммит
- `large_commits_count` & `large_commits_percentage`: Коммиты >500 строк
- `small_commits_count` & `small_commits_percentage`: Коммиты ≤50 строк

**Визуальный дизайн**:
- Виджет на всю ширину с адаптивной сеточной компоновкой
- Несколько рядов статистики, организованных по категориям
- Цветовое кодирование элементов статистики с градиентными фонами
- Эффекты наведения и плавные переходы

**Ключевые метрики**:
- **Метрики объема**: Общие коммиты, добавленные/удаленные строки, измененные файлы
- **Метрики производительности**: Средний размер коммита, ежедневные средние
- **Метрики качества**: Распределение больших и малых коммитов

### 3. Виджет ежедневной активности
**Назначение**: Визуализирует паттерны активности коммитов по дням недели.

**Источник данных**: Объект `daily_activity` с названиями дней в качестве ключей и количеством коммитов в качестве значений.

**Визуальный дизайн**:
- Горизонтальная диаграмма с 7 столбцами (по одному на день)
- Столбцы пропорционально масштабированы в зависимости от активности
- Названия дней сокращены до 3 символов
- Градиентные эффекты заливки с тенью
- Адаптивная высота (200px на десктопе, 150px на мобильном)

**Ключевые функции**:
- **Анализ дней**: Показывает, в какие дни наибольшая/наименьшая активность
- **Распознавание паттернов**: Помогает выявить рабочие паттерны и тренды продуктивности
- **Визуальное сравнение**: Легкое сравнение между разными днями

### 4. Виджет почасовой активности
**Назначение**: Показывает паттерны активности коммитов в течение дня.

**Источник данных**: Объект `hourly_activity` со строками часов (например, "00:00", "01:00") в качестве ключей и количеством коммитов в качестве значений.

**Визуальный дизайн**:
- Горизонтальная диаграмма с 24 столбцами (по одному на час)
- Информация о часовом поясе отображается в легенде
- Повернутые метки часов для лучшей читаемости
- Разные градиентные цвета (от зеленого к желтому) для отличия от ежедневной активности
- Горизонтальная прокрутка на меньших экранах

**Ключевые функции**:
- **Анализ времени**: Выявляет часы пиковой и низкой активности
- **Осведомленность о часовом поясе**: Показывает локальный часовой пояс пользователя
- **Инсайты рабочих паттернов**: Помогает понять, когда участники команды наиболее активны

### 5. Виджет топ-контрибьюторов
**Назначение**: Отображает наиболее активных участников, ранжированных по количеству коммитов.

**Источник данных**: Массив `top_authors`, содержащий:
- `author`: Имя автора
- `commit_count`: Количество коммитов
- `percentage`: Процент от общего количества коммитов

**Визуальный дизайн**:
- Вертикальная компоновка списка с ранжированием
- Полосы прогресса, показывающие относительный вклад
- Номера рангов с акцентными цветами
- Эффекты наведения с подсветкой левой границы
- Адаптивная компоновка, которая складывается на мобильном

**Ключевые функции**:
- **Система ранжирования**: Показывает топ-10 участников с рангами
- **Анализ вклада**: Отображает как абсолютные, так и процентные метрики
- **Визуальный прогресс**: Диаграммы показывают уровни относительного вклада

### 6. Виджет паттернов сообщений коммитов
**Назначение**: Анализирует и категоризирует сообщения коммитов для выявления общих паттернов.

**Источник данных**: Массив `commit_patterns`, содержащий:
- `pattern`: Описание паттерна (например, "feat: (новые функции)")
- `count`: Количество коммитов, соответствующих этому паттерну
- `percentage`: Процент от общего количества коммитов

**Визуальный дизайн**:
- Вертикальный список, аналогичный виджету участников
- Другая цветовая схема (градиенты от зеленого к желтому)
- Описания паттернов с пояснительным текстом
- Полосы прогресса, показывающие частоту паттернов

**Категории паттернов**:
- **Конвенциональные коммиты**: feat:, fix:, docs:, style:, refactor:, test:, chore:
- **Паттерны слияния**: коммиты слияния, коммиты отката
- **Структура сообщений**: однословные коммиты, коммиты с точкой в конце
- **Прочие**: Неклассифицированные коммиты

### 7. Виджет пульса коммитов
**Назначение**: Предоставляет детальный табличный вид отдельных коммитов с всесторонней статистикой.

**Источник данных**: Массив `commit_stats`, содержащий детальную информацию для каждого коммита:
- `commit_hash`: SHA хеш (отображается как 8-символьное сокращение)
- `author`: Имя автора коммита
- `message`: Сообщение коммита (только первая строка)
- `created_at`: Временная метка коммита
- `lines_added`: Строки, добавленные в коммите
- `lines_removed`: Строки, удаленные в коммите
- `net_lines_changed`: Чистое изменение (добавлено - удалено)
- `files_changed`: Количество измененных файлов

**Визуальный дизайн**:
- Таблица на всю ширину с закрепленным заголовком
- Прокручиваемый контейнер (максимальная высота 600px)
- Цветовое кодирование ячеек статистики:
  - Зеленый для добавлений
  - Красный для удалений
  - Синий для чистых изменений
  - Желтый для количества файлов
- Адаптивный дизайн с горизонтальной прокруткой на мобильном

**Ключевые функции**:
- **Детальный вид**: Полная информация о коммитах в табличном формате
- **Цветовое кодирование**: Визуальное различие между различными типами изменений
- **Сортируемые данные**: Организованы по порядку коммитов (самые новые первыми)
- **Обрезанные сообщения**: Длинные сообщения обрезаются с подсказками

## Конвейер обработки данных

### Обработка на бэкенде (`get_dashboard.py`)

1. **Получение коммитов**: Загружает коммиты из Sfera API с настраиваемым лимитом (по умолчанию 500, максимум 5000)

2. **Анализ различий**: Для каждого коммита получает и парсит содержимое diff для расчета:
   - Добавленных/удаленных строк
   - Измененных файлов
   - Анализа типов файлов
   - Обнаружения бинарных файлов

3. **Статистические вычисления**:
   - Анализ вклада авторов
   - Распознавание паттернов коммитов с использованием regex
   - Агрегация ежедневной/почасовой активности
   - Вычисление общей статистики

4. **Агрегация данных**: Объединяет все анализы в структурированный ответ

### Обработка на фронтенде (`Dashboard.tsx`)

1. **Управление состоянием**: Управляет состояниями загрузки, обработкой ошибок и кэшированием данных

2. **Синхронизация URL**: Обновляет URL браузера с текущими выборами (проект, репозиторий, лимит)

3. **Визуализация данных**: Преобразует данные бэкенда в визуальные компоненты

4. **Адаптивная компоновка**: Адаптирует компоновку виджетов в зависимости от размера экрана

## Параметры конфигурации

### Параметры запроса
- `project`: Выбранный ключ проекта
- `repository`: Выбранное имя репозитория  
- `limit`: Количество коммитов для анализа (1-5000, по умолчанию 500)

### Параметры API
- `rev`: Git ревизия (ветка, тег или хеш коммита)
- `limit`: Максимальное количество коммитов для обработки

## Соображения производительности

### Оптимизации бэкенда
- **Параллельная обработка**: Коммиты обрабатываются пакетами по 20 для анализа различий
- **Обработка ошибок**: Сбои отдельных коммитов не останавливают весь анализ
- **Кэширование**: Результаты могут кэшироваться на основе параметров запроса

### Оптимизации фронтенда
- **Ленивая загрузка**: Виджеты рендерятся только при наличии данных
- **Адаптивный дизайн**: Оптимизированные компоновки для различных размеров экрана
- **Границы ошибок**: Элегантная обработка ошибок с функциональностью повтора

## Адаптивный дизайн

### Десктоп (≥768px)
- Многоколоночная сеточная компоновка
- Полная функциональность виджетов
- Эффекты наведения и анимации

### Планшет (768px - 480px)
- Одноколоночная компоновка
- Уменьшенные отступы виджетов
- Упрощенные взаимодействия

### Мобильный (<480px)
- Сложенная компоновка
- Горизонтальная прокрутка для таблиц
- Оптимизированные для касания взаимодействия
- Уменьшенные размеры шрифтов и отступы

## Обработка ошибок

### Ошибки бэкенда
- Сбои аутентификации (401)
- Недопустимые параметры (400)
- Ошибки сервера (500)
- Сбои обработки отдельных коммитов

### Ошибки фронтенда
- Сбои сетевых запросов
- Ошибки парсинга данных
- Ошибки рендеринга компонентов
- Пользовательские сообщения об ошибках с опциями повтора
